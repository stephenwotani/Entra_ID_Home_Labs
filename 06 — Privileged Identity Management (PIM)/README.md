# Microsoft Entra ID: Privileged Identity Management (PIM)

## 📌 Project Overview
This project explores Microsoft Entra Privileged Identity Management (PIM), focusing on just-in-time access, controlled administrative role activation, and reducing standing privileges.

## 🎯 Objectives
- Understand privileged identity management.
- Configure eligible role assignments.
- Explore just-in-time administrative access.
- Configure activation requirements.
- Review privileged access history.

## 🛠️ Technologies Used
- Microsoft Entra ID
- Microsoft Entra Privileged Identity Management
- Microsoft Entra Admin Center

## ⚙️ Implementation

1. Accessed the PIM portal.
2. Explored Microsoft Entra role management.
3. Assigned eligible administrative roles to a test user.
4. Configured role activation duration.
5. Explored MFA requirements for activation.
6. Configured approval requirements where supported.
7. Activated an eligible role.
8. Reviewed PIM audit history and assignment details.

## 🧪 Testing & Validation
- Verified eligible role assignments.
- Tested role activation.
- Confirmed activation requirements.
- Reviewed privileged access activity.

## 🔐 Security Considerations
- Minimize permanent privileged access.
- Require MFA for role activation.
- Apply approval workflows for sensitive roles.
- Limit activation duration.
- Audit privileged activity.

## 📚 Key Learnings
Developed practical understanding of just-in-time access, privileged identity governance, role activation, and administrative security.

## ⚠️ Licensing
PIM generally requires Microsoft Entra ID P2 or Microsoft Entra ID Governance licensing, depending on the feature.
