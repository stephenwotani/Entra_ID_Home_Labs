# Microsoft Entra ID: App Registrations & Application Identity

## 📌 Project Overview
This project explores Microsoft Entra application registrations and application identities, demonstrating how applications integrate with Microsoft identity services and access protected resources.

## 🎯 Objectives
- Register applications in Microsoft Entra ID.
- Understand application and service principal objects.
- Configure redirect URIs.
- Explore API permissions.
- Understand application consent.
- Examine authentication credentials.

## 🛠️ Technologies Used
- Microsoft Entra ID
- App Registrations
- Microsoft Graph
- OAuth 2.0 / OpenID Connect

## ⚙️ Implementation

1. Created an application registration.
2. Configured application name and supported account types.
3. Reviewed application client ID and tenant ID.
4. Configured redirect URI where applicable.
5. Explored API permissions.
6. Examined delegated and application permissions.
7. Explored admin consent.
8. Configured a test credential where appropriate.
9. Reviewed the associated service principal.

- Verified application registration.
- Reviewed configured permissions.
- Validated authentication settings.
- Examined application identity and access configuration.

## 🔐 Security Considerations
- Apply least privilege to API permissions.
- Avoid unnecessary admin consent.
- Protect client secrets.
- Prefer certificates or managed identities where appropriate.
- Monitor credential expiration.

## 📚 Key Learnings
Developed an understanding of application identities, API authorization, OAuth 2.0, OpenID Connect, and Microsoft Graph integration.

## ⚠️ Important
Never publish client secrets, access tokens, private keys, or credentials in a public repository.
